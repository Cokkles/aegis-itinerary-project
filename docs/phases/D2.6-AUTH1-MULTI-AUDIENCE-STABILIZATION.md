# D2.6 — AUTH-1 Multi-Audience Stabilization

## Outcome

The consolidated Apps Script runtime now validates Google ID tokens against the
primary PWA audience and every additional first-party audience configured for
AEGIS Windows or Android. The public authentication bootstrap still exposes only
the primary PWA client ID.

This is an additive authentication correction. It does not remove or rename an
action, change an OAuth scope, modify a document, or alter Calendar, Tasks,
HORIZON, KINETIC, SPARK, or SENTINEL data.

## Root cause

The modular AUTH-1 source supported `AEGIS_GOOGLE_CLIENT_IDS`, but the full
consolidated deployment candidate retained the older single-audience comparison.
Deploying that candidate caused valid Desktop tokens to fail upstream with
`Google identity token audience mismatch.` Local-only features continued to
work because they did not cross the Apps Script AUTH-1 boundary.

## Script properties

- `AEGIS_GOOGLE_CLIENT_ID` remains the primary browser/PWA client ID.
- `AEGIS_GOOGLE_CLIENT_IDS` contains additional trusted first-party client IDs.
- The plural property accepts comma-, semicolon-, whitespace-, or newline-
  separated values, or a JSON array.
- Empty values are ignored and duplicate values are removed.

Do not move the Desktop ID into the singular property. Doing so would change the
client ID returned to the PWA by `auth_config`.

## Safe diagnostics

`auth_config` now reports `trusted_audience_count` and
`additional_audiences_configured`. It never returns the additional client IDs.
This makes it possible to verify that the deployed script observed the plural
property without disclosing the trusted audience list.

## Deployment and validation gate

1. Replace the Apps Script project code with
   `apps-script/Code.calendar-prepare-v1.gs` from this checkpoint.
2. Create a new web-app deployment/version; do not only save the editor.
3. Open `?action=auth_config` on the deployed URL and confirm:
   - `backend_version` is `2.6.6`;
   - `configured` is `true`;
   - `additional_audiences_configured` is `true`;
   - `trusted_audience_count` is at least `2`.
4. In AEGIS Windows, refresh the workspace and test, in order:
   - AEGIS connection;
   - Running Notes sync using disposable text;
   - Calories/KINETIC using a disposable entry;
   - HORIZON generation only if a new report is actually desired.
5. Confirm the PWA still signs in and loads its dashboard. Confirm Android on its
   next normal use if its OAuth client is included in the plural property.

## Rollback

Redeploy the Apps Script version immediately preceding backend `2.6.6`. No data
migration or client rollback is required. The pre-correction consolidated file
is preserved in Git checkpoint `0ae0eed`.
